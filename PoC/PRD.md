# PRD: MX GenAI Power User Level 4 과제제안서 평가 에이전트

## 1) 문서 정보
- **문서명**: PRD (Product Requirements Document)
- **프로젝트명**: MX 과제제안서 자동 평가 에이전트
- **작성일**: 2026-03-27
- **요청 배경**: 인재개발 요청에 따라 GenAI Power User Level 4 지원자 과제제안서(블라인드) 서류심사를 기한 내 수행

---

## 2) 배경 및 목적
### 배경
- MX 지원자 과제제안서 심사가 대량(후보군 기준 약 201명, 심사대상 262명)으로 발생
- 수작업 심사 시 시간 소요 및 평가 편차 발생 가능

### 목적
- 과제제안서 압축파일을 자동 해제하고,
- 평가 기준에 따라 점수/등급 및 종합의견(H열)을 생성하여,
- 최종 엑셀 결과물을 빠르게 산출

---

## 3) 범위
### In Scope
- 입력 ZIP 해제
- 제안서 문서 파싱(파일명/접수번호 매핑)
- 항목별 평가등급(A+, A, B+, B, C) 생성
- 종합의견(H열) 자동 작성
- 결과 파일 저장

### Out of Scope
- 메일 송신/자동 회신
- 인사 시스템 연동
- 최종 합격 확정 의사결정 자동화(사람 검토 필요)

---

## 4) 입력/출력 요구사항
### 입력
- `MX 과제제안서 (1).zip`
- 평가 템플릿 엑셀 (예: `1. MX_세부평가_전략 의견 추가.xlsx`)

### 처리
1. ZIP과 동일한 이름의 폴더 생성 후 압축 해제
2. 제안서별 평가 수행
   - **심사 항목(블라인드)**
     1) 경영성과 50%
     2) 혁신/확산성 20%
     3) AI기술 및 데이터 30%
   - **평가 척도**: A+, A, B+, B, C
   - **엑셀 반영**:
     - 종합의견(H열)
     - 세부항목 점수/등급(J~S, 템플릿 기준)
   - 불합격 사유는 납득 가능하게 서술
   - 1차 필터링 후보 인원(예: 201명) 맥락 반영

### 출력
- `MX_세부평가_전략 의견 추가.xlsx`
- 처리 로그(건수, 누락건, 오류건)

---

## 5) 사용자 시나리오
1. 사용자가 ZIP과 템플릿 엑셀을 지정 위치에 둔다.
2. 에이전트를 실행한다.
3. 에이전트가 압축 해제 및 평가를 수행한다.
4. 완료 후 결과 엑셀 파일을 생성한다.
5. 심사자가 결과를 검토/수정 후 최종 제출한다.

---

## 6) 기능 요구사항 (Functional Requirements)
### FR-01 압축 해제
- 시스템은 입력 ZIP과 동일한 이름의 폴더를 생성하고 내부 파일을 해제해야 한다.

### FR-02 파일 매핑
- 시스템은 접수번호/파일명 규칙으로 제안서와 엑셀 행을 매핑해야 한다.
- 매핑 실패 시 해당 행에 미평가 사유를 기록해야 한다.

### FR-03 평가 엔진
- 시스템은 3대 항목 가중치(50/20/30)를 적용해 평가를 계산해야 한다.
- 세부항목 결과를 A+, A, B+, B, C 중 하나로 산출해야 한다.

### FR-04 종합의견 생성
- 시스템은 장점/보완점/판단(합격권·보완권) 포함 종합의견을 생성해야 한다.
- 불합격권인 경우 사유를 구체적으로 작성해야 한다.

### FR-05 결과 저장
- 시스템은 지정된 출력 파일명으로 결과 엑셀을 저장해야 한다.

### FR-06 실행 결과 리포트
- 시스템은 처리 건수/누락 건수/오류 건수를 출력해야 한다.

---

## 7) 비기능 요구사항 (Non-Functional Requirements)
- **성능**: 262건 기준 실무 허용 시간 내 처리(예: 수 분~수십 분)
- **신뢰성**: 개별 파일 오류가 전체 중단으로 이어지지 않아야 함
- **추적성**: 어떤 기준으로 평가됐는지 로그/근거 확인 가능해야 함
- **재실행성**: 동일 입력에 대해 재현 가능한 결과 제공

---

## 8) 평가/판정 정책
- 합격 기준: **100점 만점 중 80점 이상**
- 동일/유사 과제라도 **역할 구분**에 따라 합/불을 다르게 판정 가능
- 자동평가 결과는 1차안으로 사용하고, 최종 판정은 심사자 검토 반영

---

## 9) 리스크 및 대응
- OCR/문서 파싱 오류 → 파일 포맷 검증 및 예외 처리
- 파일명 규칙 불일치 → 수동 매핑 테이블 보완
- 키워드 기반 평가의 해석 한계 → 심사자 검토 단계 필수

---

## 10) 수용 기준 (Acceptance Criteria)
- [ ] ZIP 해제 폴더가 생성된다.
- [ ] 제안서-엑셀 행 매핑이 수행된다.
- [ ] H열 종합의견이 채워진다.
- [ ] J~S(세부항목)가 등급으로 채워진다.
- [ ] 결과 파일이 지정명으로 저장된다.
- [ ] 처리 요약(처리/누락/오류) 로그가 확인된다.

---

## 11) 운영 메모
- 현재 프로세스는 자동화 초안(PoC) 목적
- 실제 제출 전 샘플 검증 및 기준표(2nd sheet) 정합성 최종 확인 권장
