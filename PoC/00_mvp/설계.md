# 보안 LLM Gateway MVP 설계 (Python)

## 1. 목표
- **구현 흐름도(도 1~7)**와 매핑되는 최소 동작 구현
- **실시예 로그캡처(정상/차단/폴백/혼합 라우팅)** 자동 확보
- **PoC 데모 가능**한 웹 UI + 백엔드 구성

---

## 2. MVP 범위 (특허 핵심만)
특허 핵심요소 중 MVP에서 반드시 포함할 최소 기능:
1) 민감도 점수화(간단 규칙 기반)
2) 정책 기반 라우팅(내부/외부)
3) 세그먼트 단위 혼합 라우팅(문장 단위 split)
4) 응답 2차 재검사(금칙어/민감패턴)
5) 감사로그 저장(JSONL)

> 제외(후속): 고도 NER 모델, 복잡 정책 콘솔, 실제 기업 IAM 연동

---

## 3. 기술 스택 제안
- **Backend**: Python + FastAPI
- **Frontend**: HTML + JS (Jinja2 템플릿 또는 순수 SPA)
- **Server**: Uvicorn
- **Log 저장**: JSONL 파일 (`logs/audit_YYYYMMDD.jsonl`)
- **설정**: `.env`

---

## 4. 블록 설계 (흐름도 대응)

###[A] Input/API Layer
- 역할: 사용자 입력 수신
- 엔드포인트:
  - `POST /api/analyze` : 라우팅+응답 생성
  - `GET /api/logs` : 최근 로그 조회

###[B] DLP & Risk Scorer
- 역할: 민감정보 탐지 + 위험도 점수 계산
- 규칙 예시:
  - 이메일/전화/주민번호 패턴
  - 키워드(프로젝트코드, 원가, 수율, 고객사명 등)
- 출력:
  - `risk_score` (0~100)
  - `findings[]`

###[C] Policy Engine
- 역할: 점수 기준으로 경로 결정
- 정책 예시:
  - score < 30: external
  - 30 <= score < 70: hybrid
  - score >= 70: internal
- fallback 규칙:
  - external 오류 시 internal로 전환

###[D] Router / LLM Connector
- 역할: internal/external/hybrid 호출
- MVP에서는 실제 API 대신 Mock 가능 + 옵션으로 실제 호출
- hybrid:
  - 문장 분할 후 고위험 문장 internal, 저위험 문장 external

###[E] Post-Check (2차 DLP)
- 역할: 응답 텍스트 재검사
- 위반 시:
  - `block` 또는 `mask` 처리

###[F] Audit Logger
- 역할: 감사로그 저장
- 저장 필드:
  - request_id, timestamp
  - risk_score, route, policy_version
  - fallback_used, blocked
  - reasons[], model_ids
  - input_preview, output_preview

###[G] Web UI
- 화면 요소:
  - 입력창
  - 위험도/탐지결과
  - 라우팅 결과
  - 응답
  - 로그 캡처 버튼(또는 자동 저장)

## 6. API 설계(초안)
### POST /api/analyze
입력:
```json
{
  "text": "사용자 입력",
  "force_mode": "auto|internal|external|hybrid"
}
```
출력:
```json
{
  "request_id": "...",
  "risk_score": 65,
  "findings": ["email", "project_code"],
  "route": "hybrid",
  "fallback_used": false,
  "blocked": false,
  "output": "...",
  "postcheck": {"violations": []}
}
```

### GET /api/logs
- 최근 N건 감사로그 반환

## 7. 실시예 로그캡처 시나리오
1) **정상**: 비민감 텍스트 → external → 통과
2) **차단**: 고민감 텍스트 + 응답 재검사 위반 → blocked
3) **폴백**: external 강제 실패(mock) → internal 전환
4) **혼합 라우팅**: 민감 문장 + 비민감 문장 혼재 → hybrid

각 시나리오마다 `logs/`에 JSONL 남기고, 캡처용 결과 JSON 저장.

---

## 9. 데모 시연 스크립트(요약)
- 입력 1: 일반 뉴스 요약 요청 → external
- 입력 2: 기밀 키워드 포함 요청 → internal 또는 hybrid
- 입력 3: external 실패 상황 재현 → fallback
- 입력 4: 응답에 민감정보 포함된 경우 → post-check 차단
