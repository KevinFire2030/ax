# 특허 제출패키지 v2 (도면 상세 설명)
## 과제명
민감정보 위험도 기반 내부·외부 대규모 언어모델 동적 라우팅 보안 게이트웨이 장치 및 방법

---

## 도 1. 시스템 구성도(상세)
도 1은 보안 LLM 게이트웨이(100)가 입력 수신 모듈(110), 민감정보 탐지 모듈(120), 위험도 산정 모듈(130), 정책 엔진(140), 라우팅 모듈(150), 토큰화/가명화 모듈(160), 역치환 모듈(170), 응답 재검사 모듈(180), 감사 로그 모듈(190)을 포함하고, 내부 LLM(200) 및 외부 LLM(300)과 통신하는 구성을 나타낸다.

## 도 2. 전체 처리 순서도(상세)
(1) 사용자 요청 수신 → (2) 민감 엔티티 탐지 → (3) 위험도 점수 계산 → (4) 정책 매칭 → (5) 라우팅 결정(내부/외부/혼합) → (6) LLM 호출 → (7) 응답 수신 → (8) 응답 재검사 → (9) 반환/마스킹/차단 → (10) 감사 로그 기록 순으로 동작한다.

## 도 3. 세그먼트 분할 하이브리드 라우팅(상세)
입력 프롬프트를 문장 또는 의미 단위 세그먼트로 분할하고, 각 세그먼트의 위험도에 따라 내부 경로와 외부 경로를 병렬 적용한다. 이후 결과를 재조합하여 단일 응답으로 통합한다. 이를 통해 전체 내부처리 대비 품질을 향상시키고, 전체 외부처리 대비 보안을 강화한다.

## 도 4. 토큰화/역치환 구조(상세)
외부 전송 전 민감 문자열을 토큰(예: ORG_1, PERSON_3)으로 치환한다. 토큰-원문 매핑은 암호화 저장소에 저장되며 접근권한이 제한된다. 응답 단계에서는 허용 토큰 집합에 한해 역치환하며, 미허용 토큰이나 신규 민감정보는 차단 또는 추가 마스킹한다.

## 도 5. 정책 엔진 의사결정 트리(상세)
정책 엔진은 사용자 역할, 데이터 등급, 업무 유형, 시간대, 모델 정책(허용 리전/로그 조건/모델 신뢰도)을 입력받아 허용 경로를 결정한다. 예를 들어 고기밀+고위험은 내부 LLM 고정, 저기밀+저위험은 외부 LLM 허용, 중위험은 세그먼트 혼합 경로를 선택한다.

## 도 6. 응답 재검사 및 차단 처리(상세)
응답 텍스트에 대해 2차 DLP를 수행하여 신규 민감정보, 정책 금지 패턴, 재식별 단서 포함 여부를 판단한다. 위반 시 (a) 전체 차단, (b) 부분 마스킹 후 반환, (c) 사용자 경고 후 재요청 유도 중 하나를 수행한다.

## 도 7. 감사 로그 및 추적 인터페이스(상세)
감사 로그에는 요청 ID, 사용자/시스템 식별자, 위험도 점수, 적용 정책 버전, 라우팅 모델 ID, 차단 사유 코드, 처리 시간, 결과 상태를 저장한다. 감사자는 이력을 조회하여 "왜 해당 요청이 내부 또는 외부로 라우팅되었는지"를 추적할 수 있다.

## 도면 부호
100: 보안 LLM 게이트웨이
110: 입력 수신 모듈
120: 민감정보 탐지 모듈
130: 위험도 산정 모듈
140: 정책 엔진
150: 라우팅 모듈
160: 토큰화/가명화 모듈
170: 역치환 모듈
180: 응답 재검사 모듈
190: 감사 로그 모듈
200: 내부 LLM
300: 외부 LLM
