## 한 줄 요약

쿠팡 애즈는 광고주 성장을 돕는 세일즈 운영의 수동 분석, 진단, 우선순위화, 피칭 과정을 AI 광고 컨설턴트로 전환해 더 많은 광고주에게 일관된 고품질 컨설팅을 제공하려 한다.

## 핵심 메시지

발표는 쿠팡 애즈 세일즈 팀이 광고주의 빠른 성장을 돕기 위해 AI 광고 컨설턴트를 구축한 여정을 소개했다. 단순히 AI 솔루션을 만드는 것과 이를 실제 비즈니스 운영 수준에서 상품화해 안정적으로 쓰는 것은 전혀 다른 문제라는 점이 출발점이었다.

쿠팡 애즈의 고객은 대형 브랜드만이 아니라 쿠팡 판매자이자 광고주인 중소상공인이 많다. 발표자는 광고주의 70% 이상이 SME이며, 이들에게 광고 용어와 성과 지표는 어렵고 광고비 집행은 위험하게 느껴질 수 있다고 설명했다. 따라서 쿠팡 애즈의 목표는 광고주가 광고를 더 쉽게 이해하고 더 좋은 성과를 낼 수 있도록 돕는 것이다.

## 문제 정의

기존 세일즈 운영은 AE가 여러 내부 도구와 BI 대시보드, CRM 히스토리, 본인의 경험을 바탕으로 광고주와 캠페인을 분석하고 피칭하는 구조였다. 그러나 광고주와 캠페인의 수가 매우 많아 고품질 컨설팅을 제공할 수 있는 범위가 제한적이었다.

발표에서 제시된 규모는 상당했다. SME 담당 AE는 최대 600명의 광고주를 담당하고, 대형 광고주는 약 60명 수준을 담당한다. 분석 대상 캠페인은 28만 3천 개 이상으로 언급됐다. 반면 한 명의 AE가 한 주에 소화하는 피칭은 약 150건 수준이라, 수요와 공급 사이에 약 500배 격차가 있었다.

또한 기존 ML 기반 추천이나 템플릿은 있었지만 AE들이 실제 현장에서는 잘 사용하지 않는 경우가 있었다. 이유는 데이터나 템플릿이 현재 고객의 맥락, 광고주의 성향, 실제 대화 상황에 맞지 않았기 때문이다. 발표자는 “데이터는 있지만 컨텍스트가 부족한” 문제가 핵심이었다고 설명했다.

## AI 광고 컨설턴트의 목표

쿠팡 애즈가 정의한 AI 광고 컨설턴트의 목표는 AE가 수시간 걸려 하던 일을 한 번의 대화와 몇 분 안의 프로세스로 압축하는 것이었다. 주요 목표는 다음과 같다.

- 여러 도구에 흩어진 캠페인 데이터를 1분 안에 하나의 뷰로 통합
- AE 경험에 의존하던 성과 하락 원인 분석을 진단 플레이북 기반으로 자동화
- 어떤 캠페인을 먼저 피칭할지 AI가 우선순위를 계산
- 광고주별 맥락과 성향에 맞는 피칭 스크립트와 리포트 생성
- 추천 적용 시 예상 성과 개선 효과까지 설명
- AE별 편차를 줄이고 컨설팅 품질을 일관되게 유지

## 시스템 설계

발표자는 AI 광고 컨설턴트의 시스템 아키텍처를 네 가지 영역으로 설명했다.

첫째, 사용자 인터페이스는 별도 애플리케이션이 아니라 기존 애드센터와 세일즈 툴에 임베딩된 챗봇 형태로 설계했다. AE가 기존 업무 흐름을 크게 바꾸지 않고 사용할 수 있게 한 것이다.

둘째, LLM 솔빙 레이어는 데이터 리트리벌 레이어와 API 레이어로 구성됐다. 초기에는 빠른 검증을 위해 사용 가능한 API와 데이터 웨어하우스 접근을 활용했고, 이후 ClickHouse MCP와 팩트 테이블 기반 스키마 접근으로 일관된 데이터 조회 구조를 만들었다.

셋째, API 레벨에서는 LangGraph 기반 에이전트를 구성하고, 쿼터와 로깅 같은 서비스 모듈을 포함해 운영 가능한 서버 구조를 만들었다.

넷째, 쿠팡 AI 게이트웨이를 통해 프롬프트 인젝션, PII, 보안, 프라이버시 관련 위험을 처리하고, 모든 입력과 출력은 로깅 시스템으로 모니터링했다. 축적된 데이터는 전처리와 필터링을 거쳐 오픈소스 기반 모델의 지도 파인튜닝과 DPO에도 활용했다.

## 에이전트 동작 흐름

내부 에이전트는 ReAct 기반 오케스트레이터를 사용해 질문 라우팅과 도구 호출을 결정한다. 주요 플로우는 캠페인 상세 진단, 데이터 질의, 단순 조회 응답으로 나뉘며, 핵심은 캠페인 상세 진단을 위한 딥다이브 파이프라인이다.

이 파이프라인은 먼저 캠페인을 선택하고 성과 데이터를 확인해 진단 필요성을 판단한다. 이후 카테고리 수준 정보, 벤치마크 데이터, 키워드 데이터 등을 모아 LLM 입력으로 사용한다. 분석 단계에서는 25개 이상으로 구성한 진단 플레이북을 통해 성과 하락 원인을 찾고, 추천 레이어는 기존 ML 기반 추천 결과와 진단 원인을 매칭한다. 마지막 피치 레이어는 하이브리드 렌더링 방식으로 리포트를 생성하고, Evaluator 단계가 숫자와 결과를 재검증한다.

## 중요한 설계 원칙

가장 중요한 원칙은 파이프라인의 순서와 분기는 코드가 결정하고, LLM은 분석과 판단에 집중하게 한다는 것이다. 발표자는 LLM에게 전체 흐름 제어까지 맡기면 통제 가능성과 결과 보장을 잃게 된다고 설명했다.

추천 역시 LLM에게 직접 맡기지 않았다. 쿠팡이 이미 보유한 ML 기반 추천과 예측 모델의 정확도와 커버리지를 버리는 대신, AI는 진단 결과와 기존 추천 체계를 연결하고 설명하는 역할을 맡았다. 또한 하이브리드 렌더링 방식으로 숫자 할루시네이션을 방지하고, 실제 수치 검증은 시스템적으로 수행했다.

## 성과와 과제

알파 런칭 후 가장 크게 드러난 문제는 비용과 지연 시간이었다. 캠페인 수가 많아 비용이 크게 증가했고, 기존 수시간 작업을 10분 안으로 줄였음에도 현장에서는 여전히 느리다는 피드백이 있었다.

최적화 결과 비용은 62% 절감했고, 지연 시간은 7분에서 약 1분 30초 수준으로 줄였다고 설명했다. 목표는 30초 이내 응답이다. LLM은 결론, 서술, 이슈 요약, 액션 추천에 집중시키고, 숫자와 계산은 통제 가능한 데이터 시스템과 검증 루프가 담당하도록 설계했다.

## 시사점

- AI 도입은 기술 구현보다 실제 업무 흐름과 운영 맥락 이해가 먼저다.
- 세일즈 현장의 핵심 문제는 데이터 부족이 아니라 컨텍스트에 맞는 해석과 실행 전략 부족이었다.
- LLM은 전체 자동화의 중심이 될 수 있지만, 모든 판단과 분기를 맡겨서는 안 된다.
- 기존 ML 추천 자산과 LLM 기반 분석을 결합하면 더 현실적인 AI 운영 도구를 만들 수 있다.
- 할루시네이션을 막기 위해 숫자, 분기, 검증은 시스템적으로 통제해야 한다.
- AI 솔루션은 속도, 비용, 품질, 보안까지 함께 최적화되어야 실제 현장에 안착할 수 있다.
