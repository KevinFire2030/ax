# 제안서 자동 평가 에이전트 (PoC)

MX 과제제안서 ZIP을 업로드하면, LLM + 배점표 기준으로 평가하고 엑셀 결과를 생성하는 Streamlit 기반 PoC입니다.

---

## 1. 실행방법

### 1-1) `.env` 파일 설정
1. 템플릿 복사
```bash
cd "E:\ax\genAI lv4\PoC"
copy .env.example .env
```

2. `.env` 값 입력 (예시)
```env
# 공통
LLM_PROVIDER=openai
FIRST_ROUND_X_PENALTY=8

# OpenAI
OPENAI_API_KEY=...
OPENAI_MODEL=gpt-4o-mini
OPENAI_BASE_URL=https://api.openai.com/v1

# Gauss
GAUSS_API_KEY=...
GAUSS_MODEL=...
GAUSS_ENDPOINT=...
GAUSS_MIN_INTERVAL_SEC=22
```

> ## ⚠️ 매우 중요
> `.env`에 **API KEY를 반드시 입력해야** 앱이 동작합니다.
> - OpenAI 선택 시: `OPENAI_API_KEY` 필수
> - Gauss 선택 시: `GAUSS_API_KEY` + `GAUSS_ENDPOINT` 필수
> 
> API KEY가 비어 있으면 평가 시작 시 즉시 오류가 발생합니다.

- `FIRST_ROUND_X_PENALTY`: 1차 심사결과가 X일 때 감점(기본 8점)
- `GAUSS_MIN_INTERVAL_SEC`: Trial 호출 제한 대응(분당 3회 기준)

---

---

### 1-3) 실행
```bash

```

브라우저가 자동으로 열리지 않으면, 콘솔에 출력된 로컬 URL(보통 `http://localhost:8501`)로 접속하세요.

---

### ⚠️ 주의사항
- ZIP 압축 해제 시 제안서 문서(docx)에 **DRM이 없어야** 정상 파싱/평가됩니다.
- DRM/암호/손상 파일은 본문 추출 실패로 평가 누락될 수 있습니다.

## 2. 사용법 (웹 UI)

## 2-1) 입력
- **LLM 선택**: `openai` 또는 `gauss`
- **평가 문서 수**: 기본 5개(데모 목적)
- **ZIP 파일 선택**: 제안서 `.zip`
- **시작 버튼**: `평가 시작`

### ⚠️ 주의사항 (Gauss)
- Gauss Trial은 API 호출 제한이 있어 **1분 3회** 수준으로 호출됩니다.
- 앱 내부에서 호출 간격(`GAUSS_MIN_INTERVAL_SEC`)을 적용하므로 처리 시간이 더 길 수 있습니다.

---

## 2-2) 처리
처리 영역에서 아래가 실시간 표시됩니다.
- ZIP 저장/압축해제 로그
- 문서별 LLM 평가 진행 상태
- 진행률(progress bar)
- 최신 평가 결과(파일명, 접수번호, 점수, 의견 요약)
- 누적 결과 테이블(문서별 총점/판정)

---

## 2-3) 출력
출력 영역에서 아래를 제공합니다.
- 평가 결과 분석 요약(상세)
  - 평가 건수
  - 합격/불합격 건수
  - 1차 X 패널티 적용 건수
  - 불합격 상세 사유 재작성 건수
  - 처리 시간
  - 총 사용 토큰(입력/출력 분리)
- 결과 파일 다운로드
  - `평가표_YYYYMMDD_HHMMSS.xlsx`

  - 1차 심사결과(X) 패널티 반영
  - 92/262 비율 기반 최종 합/불 판정
  - 불합격 사유 LLM 상세 재작성
  - 합격/불합격 시트 자동 생성

- 본 PoC 요구사항/목표/범위/수용기준 정리 문서

### 3-3) `채점표.md`

- 실행에 필요한 Python 라이브러리 목록

## 4. 평가 방법

## 4-1) 채점표
총 100점 배점 구조를 사용합니다.
- 경영성과 50점 (8개 항목)
- 혁신성/확산성 20점 (4개 항목)
- AI기술/데이터 30점 (7개 항목)

각 세부항목은 `우수/양호/보통/미흡`으로 평가되며, 항목별 배점표에 따라 점수 환산합니다.
(예외: `기술 선정 이유`는 보통 없음)

---

## 4-2) LLM 호출
### 프롬프트(콜아웃)
> 시스템 프롬프트는 19개 세부항목 각각을 `우수/양호/보통/미흡`으로 분류하도록 강제하며,
> JSON 형태로 `rubric_levels`와 `opinion`을 반환하도록 요구합니다.

### 인/아웃
- **입력(Input)**
  - 파일명
  - 제안서 본문 텍스트(길이 제한 적용)
  - 평가 지시 프롬프트
- **출력(Output)**
  - `rubric_levels`: 세부항목별 레벨
  - `opinion`: 과제 종합의견

---

## 4-3) 평가 결과 저장
- 엑셀 평가 컬럼 업데이트
  - 세부 평가항목(총 19개) 컬럼 반영
  - 과제 종합의견(H)
  - 최종판정(I)
  - 총점(J)

- 1차 심사결과 반영
  - 1차 결과가 `X`인 경우 **패널티 감점** 적용
  - 감점값: `FIRST_ROUND_X_PENALTY` (기본 8)

- 총점
  - 배점표 기반 점수 합산 후 최종점수 산정

---

## 4-4) 최종 판정
- 판정 기준: **92/262 비중**
- 방식:
  1. 최종점수 내림차순 정렬
  2. 상위 quota(비율 반영) = `합격`
  3. 나머지 = `불합격`

- 최종 판정 이후 자동 후처리:
  - `합격`만 필터링하여 **합격 시트** 생성
  - `불합격`만 필터링하여 **불합격 시트** 생성
  - 즉, 결과 파일에는 메인 시트 외에 합/불 전용 시트가 함께 추가됨

---

## 4-5) 불합격의 경우
- `불합격` 건은 종합의견을 추가 LLM 호출로 재작성
- 목표: 불합격 사유를 더 납득 가능하고 상세하게 제시

### 작성 프롬프트(요약)
- 근거 중심 작성
- 부족점 분리(경영성과 / 혁신·확산 / AI·데이터)
- 재평가를 위한 보완 액션 제시
- 5~8문장 상세 설명

## 별첨 A. 구조도 (플로우차트)

```mermaid
flowchart TD
    A[사용자: Web UI에서 LLM 선택/ZIP 업로드] --> B[입력 검증\n.env/API KEY 확인]
    B --> C[ZIP 저장 및 압축 해제]
    C --> D[DOCX 목록 추출\n(설정된 건수만 평가)]

    D --> E[문서별 LLM 평가 호출\n19개 세부항목 레벨 + 종합의견 생성]
    E --> F[배점표(100점) 환산\n경영성과/혁신·확산/AI·데이터]
    F --> G{1차 심사결과 X?}
    G -- Yes --> H[X 패널티 적용\n(FIRST_ROUND_X_PENALTY)]
    G -- No --> I[패널티 없이 점수 확정]
    H --> J[최종점수 확정]
    I --> J

    J --> K[메인 시트 업데이트\nH: 종합의견, I: 최종판정, J: 총점, 세부항목 컬럼]
    K --> L[전체 점수 내림차순 정렬]
    L --> M[92/262 비중으로 최종 합/불 판정]

    M --> N{불합격인가?}
    N -- Yes --> O[LLM 재호출\n불합격 사유 상세 재작성]
    N -- No --> P[합격 의견 유지]
    O --> Q[메인 시트 종합의견 갱신]
    P --> Q

    Q --> R[합격/불합격 필터링]
    R --> S[합격 시트 생성]
    R --> T[불합격 시트 생성]
    S --> U[결과 엑셀 저장\n평가표_YYYYMMDD_HHMMSS.xlsx]
    T --> U
    U --> V[출력: 요약/처리시간/토큰/다운로드]
```

### 구조도 설명 요약
- **입력 단계**: LLM 선택, ZIP 업로드, `.env`/API KEY 검증
- **평가 단계**: LLM이 세부항목 레벨+의견 생성 → 배점표 점수화 → 1차 X 패널티 반영
- **판정 단계**: 92/262 비중 컷으로 합격/불합격 결정
- **후처리 단계**: 불합격 건 의견 상세 재작성, 합/불 시트 분리 생성
- **출력 단계**: 결과 파일 저장 및 UI 요약(처리시간/토큰 포함)
